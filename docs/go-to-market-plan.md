# Digital Go-to-Market Plan

## Product / Prototype Name
**Lemon — Smart Campus Lost-and-Found System**

## Target Early Users
The primary early users are university undergraduate students who frequently lose or find baseline items (IDs, calculators, USB drives, keys, bags) across high-density campus facilities. Secondary users include campus security staff and facility processing clerks who test the administrative status update workflows.

## Main Value Proposition
A centralized, web-based platform that helps students quickly report, search by campus building and category, and track lost and found items in one privacy-first portal.

## Channel Plan

| Channel | Target User | Message Angle | User Action Expected | Metric to Track | Why This Channel Fits |
| --- | --- | --- | --- | --- | --- |
| **Class Chat (LINE / Discord)** | Students | Stop searching multiple scattered chat groups for lost items | Click prototype demo link | Number of link clicks & page views | Students interact in class chat groups every day |
| **Campus Poster with QR Code** | Students on campus & Security Staff | Report or search for lost items in seconds | Scan QR code | Number of QR scans | Reaches users directly at high-density loss locations (Library, Student Center) |
| **Social Media (Facebook / Instagram)** | Student Community | Find lost items faster with one central web portal | Visit prototype demo & test workflow | Post engagements and CTA clicks | High daily student reach across university social channels |
| **Student / Staff Email Outreach** | Security Staff & Club Leaders | Test our Smart Campus Lost-and-Found prototype to streamline logistics | Try demo & submit feedback | Email link clicks & feedback responses | Reaches campus administrators and student organization leaders directly |


## Launch Sequence
1. Finalize the landing page gateway ([`../prototype/project/index.html`](../prototype/project/index.html)) and live demo link.
2. Share short launch messages in class chat groups and student community channels.
3. Display posters with QR codes near high-density campus facilities (Main Library, Cafeteria, Science Building).
4. Collect user experience feedback using the feedback form ([`feedback-form.md`](feedback-form.md)) and acquisition metrics ([`acquisition-metrics.md`](acquisition-metrics.md)).
5. Refine prototype interface and status filter usability based on customer validation feedback.

## Risk and Mitigation

| Risk | Mitigation |
| --- | --- |
| Students ignore the prototype | Use short, clear marketing messages highlighting the time saved vs. checking multiple chat groups. |
| Low number of early testers | Engage student clubs, class peers, and campus security staff to participate in initial testing. |
| Users encounter interface bugs | Conduct internal scenario testing across mobile and desktop viewports before launch. |
| QR code or link does not work | Verify live GitHub Pages URLs and QR codes across multiple mobile devices prior to poster distribution. |
